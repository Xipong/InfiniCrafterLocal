# Читаемый аудит полного запроса

`tools/diagnostics/prompt_audit.py` превращает сохранённый JSON запроса в один локальный HTML-файл. Не вызывает модель, не требует сервера или внешних библиотек, не меняет генерацию и ничего не отправляет в сеть.

Для сохранённого **предмета** (`item.json`) и его Author / Visual / VFX исходников используйте отдельный [аудит крафта](../craft-audit/README_RU.md). Он показывает фактический wire, связывает его с каноническими описаниями параметров и выполняет статические проверки. Просмотрщик запросов на этой странице объясняет переданный модели контекст; запрос не является результатом исполнения предмета.

## Быстрый запуск

Из корня репозитория (Windows: `py` вместо `python`, если используется Python Launcher):

```sh
python tools/diagnostics/prompt_audit.py "путь/к/запросу.json"
```

Рядом появится `запрос.audit.html`. Открыть браузером. Можно явно выбрать новые выходные файлы:

```sh
python tools/diagnostics/prompt_audit.py "request.json" --out "craft-audit.html" --markdown "craft-source.md"
```

Уже существующие файлы не перезаписываются. Исходник не меняется. Python 3.10+; только стандартная библиотека. Для быстрого доступа в Windows можно перетащить JSON на `tools/diagnostics/READ_PROMPT.bat`.

## Какой JSON открыть

- Полный реальный крафт: `LocalGenerator/cache/stage_requests/*.json` (при нестандартном `INFINI_CACHE_DIR` — соответствующий каталог). Сопоставить `recipeKey`, `stage` и `recipeId`. Запись содержит **sanitized сообщения до provider conversion**, не HTTP-запрос. `sanitized: true` означает, что диагностика заменила часть данных; читатель не восстанавливает удалённые значения. Для нового крафта запись зависит от `INFINI_TRACE_PROMPTS`.
- Офлайн-захват `tools/diagnostics/measure_llm_request_sizes.py`: `*.builder.json` или `*.http-body.json`. В builder-обёртке `evidence` — дополнительный контекст, не обязательно переданный модели. HTTP body показывает транспортную форму, включая schema/response-format, если они сохранены.
- Поддерживается самостоятельный dossier JSON, Chat Completions `messages`, Responses `input` / `instructions` и JSON внутри `content` / `text`.

Каждая стадия сохраняется отдельно. Один Author-файл не представляет собой все будущие Visual/VFX/Repair-вызовы. Утилита не придумывает отсутствующие стадии и не запускает их.

## Как читать

1. **Прочитать крафт**: известные разделы представлены как исходные предметы, инструкции принятия решений, форма ответа и карточки возможностей. Содержание назначений и инструкций оставлено дословно, без LLM-перевода. Для capability-параметров отдельно видны обязательность, тип, диапазон, варианты, default/neutral, условия пропуска, дополнительные ограничения и ссылки. Это удобный обзор, а не новая авторитетная схема.
2. **Полный исходник по полям**: все поля, включая неизвестные читателю. Многострочные строки не спрятаны в `\n`; объекты и массивы раскрываются. Ссылки ведут к конкретному исходному полю. `/...` — JSON Pointer с экранированием `~0` / `~1`; `::` — вход в JSON, который был сохранён внутри строки.
3. Поиск находит значения и исходные пути, раскрывает путь к совпадению. «Следующее» переходит к следующему совпадению; очистить поле — убрать выделение. «Раскрыть всё» удобно перед встроенным поиском браузера или печатью.
4. Размеры — **символы, не токены и не стоимость**. Текст `content` считается буквально; вложенные объекты — по compact JSON. Вложенные размеры перекрываются, их нельзя складывать. Полный размер исходного файла и SHA-256 указаны отдельно.
5. «Исходный JSON» возвращает **те же байты**, включая BOM/переносы/пробелы. «Полное дерево текстом» экспортирует полный структурированный текст исходника; это не стилистический пересказ и не отдельный вывод модели.

`paramRef` показывает заимствованную карточку и ссылку на её источник. `targetsRef` показывает разрешённые типы, остальные ссылки ведут в полный исходник. Однозначные `$defs` ссылки кликабельны; неразрешённые/неоднозначные остаются явными. Схемы не разворачиваются скрыто и не дублируются как якобы дополнительный размер запроса.

**Разные правила обязательности не смешиваются.** В capability-каталоге все перечисленные параметры обязательны, кроме `optional: true`. В JSON Schema обязательность задаёт `required`, а nullable не означает optional. Neutral не разрешает пропуск, наличие default не гарантирует безусловное автозаполнение. Исходные совместные/условные ограничения остаются рядом; читатель не валидирует крафт и не выбирает за человека, что выкинуть.

Повторяющиеся ключи в исходном JSON и не-JSON числа (NaN/Infinity) отвергаются, чтобы не потерять данные молча. Непарсируемая или неоднозначная JSON-строка внутри сообщения остаётся текстом. Очень глубокие документы могут превышать стандартный предел рекурсии Python: ошибка явная, без обрезанного отчёта.

**Приватность:** HTML и текст содержат полный входной файл, включая evidence и любые секреты, если вы сами подали несаницированный файл. Работайте локально; не публикуйте такой отчёт автоматически. Никаких автоматических редактирований, отправок или удаления инструкций нет.

### Копирование и чтение длинных инструкций

Номера пунктов теперь обычный выделяемый текст, а не маркеры CSS. Кнопки копируют отдельный пункт (с пояснением или только оригинал), весь раздел инструкций или карточку capability, включая закрытые детали. «Копировать читаемый разбор» и «Читаемый разбор .txt» используют один и тот же текст обзора; неизвестные поля по-прежнему доступны в полном дереве и его экспорте.

Если локальный HTML не имеет доступа к буферу обмена, появляется поле с полным выделенным текстом: нажмите Ctrl+C / ⌘C или используйте меню выделения. Успешное копирование не заявляется, пока браузер его не подтвердил. Escape закрывает поле и возвращает фокус кнопке.

Для шести известных инструкций Author добавлены краткие русские пояснения и тематические заголовки. Это **не полный перевод**, не новая инструкция модели и не замена оригинала. Пояснение включается только при совпадении SHA-256 всей исходной строки; новая/изменённая инструкция остаётся полностью видимой без догадок. Полный оригинал разбит на абзацы для чтения; отдельная кнопка копирует его исходные пробелы и переносы вместе с номером. Исходный JSON всегда сохраняется побайтно.
