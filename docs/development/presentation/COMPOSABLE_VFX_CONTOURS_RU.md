# Композиционные VFX-контуры

`rendererKind=contour` отделяет авторскую геометрию от способа её рисования. Это косметический слой: он не меняет атаку, hitbox или движение предмета.

## Что задаёт генератор

В `geometry.contours` находятся именованные определения. Ссылки локальны одному slot; порядок определений не важен, циклы запрещены.

| kind | Смысл |
|---|---|
| `line` | Отрезок между `from` и `to` |
| `ellipseArc` | Дуга эллипса: центр, две полуоси, начальный угол и знаковый sweep; полный оборот замыкается |
| `polyline` | Авторская последовательность точек |
| `transform` | Ссылка `source`, затем масштаб по осям → поворот → перенос |
| `concat` | Упорядоченные `sources` с совпадающими концами; необходимый мостик автор задаёт отдельной линией |
| `trim` | Интервал normalized arclength `start/end` с сохранением внутренних углов; убывающий интервал явно разворачивает направление, равные значения дают точку, wrap отсутствует |
| `close` | Ссылка `source`, явные промежуточные `via`, затем возврат к первой точке; пустой `via` даёт хорду |

`geometry.draws` независимо выбирает:

- `stroke`: контур, ширина **в мировых пикселях после scene transform**, `join`, `cap`, `miterLimit`;
- `fill`: один простой замкнутый контур, включая невыпуклый;
- `band`: две одинаково открытые/замкнутые границы. Начало и направление заданы автором; код не переворачивает границу для «красивого» соответствия.

У каждого draw собственный `material`: существующий texture selector, UV-преобразование, point/linear sampling, начальный/конечный RGB и opacity по времени. Для однотонной поверхности явно выбирается библиотечный `solidPixel`; остальные библиотечные и сгенерированные текстуры используют тот же материал, а не отдельный геометрический backend.

У stroke/band есть `opacityProfile` вдоль длины. Он умножается на временную opacity материала: угасание целого эффекта и прозрачность его хвоста не подменяют друг друга. Blend и draw layer принадлежат slot.

### Координаты текстуры

- Fill: `mapping.origin`, положительный `mapping.size`, явный `addressMode=clamp|repeat`. Исходные UV равны `(localPoint-origin)/size`, до общего scene transform.
- Stroke/band: `mapping.mode=stretch|repeat`, `repeatLengthPx`, `scrollPxPerTick`. У band длину для repeat задаёт первая граница; поперечная координата идёт от первой ко второй.
- `texture.uv` применяется после базового mapping, без автоматического вращения картинки по названию.

## Повторное использование вместо пресетов

Один `ellipseArc` полного оборота можно использовать для fill диска и stroke его обводки. Его масштабированная копия через `transform` вместе с исходным контуром образует band-кольцо. `trim` части исходной окружности плюс `close` с `via=[[0,0]]` образует сектор. Разные материалы используют те же определения без копирования геометрии.

Движок вычисляет точки, триангуляцию и GPU-индексы. Генератор не пишет код шейдера или ручной mesh. В текущем контракте нет произвольных выражений или скрытого выбора оружейного архетипа.

## Численная и бюджетная семантика

Fill/band имеют статическую топологию; общие `transformStart/End` интерполируются за lifetime. Stroke строится после scene transform, сохраняя мировую ширину. Настоящие пересечения stroke рисуются с буквальным повторным blend-покрытием, а не исчезают и не превращаются в неявный polygon union.

Для band объединяются arclength-узлы обеих границ и середина профиля. Авторские углы сохраняются. Нативные float32-точки ближе `1e-6` пикселя считаются совпадающими; sample fraction в пределах `1e-6` от узла использует сам узел. Численно вырожденная ячейка может стать треугольником или нулевой площадью, но контур не заменяется художественным fallback. Реальные пересечения/складки fill/band — ошибки.

Граф ограничен 16 определениями, 16 draw, 128 точками одного развёрнутого контура и 512 точками суммарно. Бюджет рисования вычисляется из всего набора draw, а не из количества slots: автору не нужны пустые slots ради увеличения лимита. Суммарная потребность одного экземпляра композиции выше 2048 единиц отклоняется; заполненные meshes не обрезаются на случайном треугольнике. Несколько одновременно живущих экземпляров продолжают делить конечный runtime-бюджет.

Историческое имя wire-поля `maxDrawCalls` означает quad-equivalent work units: mesh платит `ceil(triangles/2)`, хотя может отправляться одним GPU-вызовом. Потолок увеличен с 512 до 2048; это не выдаёт каждому предмету 2048 автоматически. Например, девять кольцевых слоёв по 64 сегмента получают вычисленные 576 единиц. Сохранённые числовые бюджеты не переписываются. Пользовательский quality multiplier по-прежнему масштабирует allowance; его общий потолок теперь 2048, поэтому multiplier=2 может использовать запас, ранее обрезавшийся на 512. Это увеличение верхней границы, не подтверждённое измерение FPS на GPU.

## Совместимость и Repair

Старые shape/history/material renderers сохраняются, в том числе их фазовая анимация и чтение реальных beam/whip/history paths. Они не мигрируют автоматически в статический contour DAG.

Repair может исправить диагностированный лист внутри `contours[]` или `draws[]`, но не получает разрешение менять соседние поля, переставлять/увеличивать массив или переписывать валидные slots. Изменения вне scope игнорируются с audit. Библиотечная текстура не создаёт PNG-job; реальный item/entity/asset selector проходит общий dependency owner с точным путём конкретного draw.

Канонический Python-контракт: `LocalGenerator/infini_local/core/vfx_contour_contract.py`. Нативная геометрия: `Common/VFX/VfxContourGeometry.cs`.
