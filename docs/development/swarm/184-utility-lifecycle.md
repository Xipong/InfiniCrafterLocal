# Generated effect lifecycle and inspection (#184)

Death, world entry and world unload retire both individual utility contributions and their aggregate through one owner. Exhaustion retires at the same boundary. Dead players reject new applications and incoming snapshots; delayed activations anchored at or before retirement cannot resurrect effects after respawn. The half-range native tick comparison handles wrap without inventing fresh duration.

`/ifceffects` exposes the canonical read-only contribution presentation, per-item exhaustion, and the last lifecycle cleanup receipt. It neither recomputes totals nor changes timers. The status timeline can consume the same snapshot. Repeated cleanup is idempotent and preserves a meaningful last retirement count; network correction occurs only when live state changed.

Native `QoL DeathBuffCleanup` covers contribution/aggregate retirement, dead admission, stale activation refusal, fresh live activation and world transition. Network receive fully decodes before declining a dead snapshot. Snapshot protocol v7 adds a server-owned life generation and server-dead acknowledgement. Actual death advances the generation once; client epochs are discarded with all client statistics. After local death, older-generation snapshots cannot repopulate effects after respawn. A server death acknowledgement arriving before the native client hook is counted once. New-life snapshots and joining observers retain normal synchronization. Version 6 snapshots fail closed; peers must use the same updated mod.

The delayed-action scheduler also fences generated-buff events against their original enqueue tick, so pre-death queued events cannot become fresh applications after respawn. Native `UtilityLifecycle Generation` exercises real serialized pre-death rejection/new-life acceptance/early acknowledgement, and `UtilityLifecycle DelayedAction` dispatches an actual queued event across death. Live multiplayer smoke remains unrun.
