# Два варианта выбора документации: результаты GPT-6 Luna

Актуальная сводка с восстановленным историческим Live10: [LIVE10_CONSOLIDATED_RU.md](LIVE10_CONSOLIDATED_RU.md). **#138 остаётся Draft/HOLD.** Первоначальные ответы и отчёт ниже сохранены.

> **HOLD / архив первой серии.** Выводы ниже относятся только к политике с резервом 50 карточек. Расширять их на роутинг вообще было ошибкой. [Контролируемое продолжение: 30 новых ответов, исправленная методика и актуальные выводы](followup/README.md). Все исходные ответы сохранены без изменений.

**Результат:** при консервативном сохранении вторичных возможностей сокращение Author-промпта небольшое. Точечный вариант дал более аккуратные первые ответы на этих четырёх задачах, но выборка мала, а валидная программа всё ещё может терять задуманную функцию. Для экономии токенов внедрение этих реализаций не оправдано; точечный вариант заслуживает дальнейшего сравнения качества после исправления выявленных пробелов контрактов.

База: `57c58d50504a7c69712e5843fa392b9a39800537`, 73 capabilities. Production pipeline, schema, validator, compiler и C# runtime не изменены. Реализации доступны как offline-функции и CLI; дополнительного production LLM-прохода нет.

## Что реализовано

Оба варианта добавляют ровно один проход выбора перед Author. Selector получает весь индекс capabilities и возвращает JSON с `catalogRevision`, `selected`, `fullCatalog`, `intent`. Неправильный ответ отклоняется; скрытого выбора или повторного запроса нет. Хост не классифицирует предметы по названию/категории и не делает семантический поиск.

| Вариант | Выбор модели | Построение документации Author |
|---|---|---|
| `groups` | Группы канонического registry | Все карточки выбранных групп + резерв вторичных функций + положительные зависимости |
| `capabilities` | Точные capability IDs | Выбранные карточки + тот же резерв + положительные зависимости |

Резерв намеренно широкий: **50 из 73 карточек**, все группы кроме movement/controller, остаются подробными независимо от выбора. В нём инструменты, снаряжение, бафы, удержание, размещение, боеприпасы, события, модификаторы и инфраструктура сущностей. Зависимость `orient_whip_to_owner_gravity → move_whip_lash` добавляет ещё одну карточку даже при пустом выборе.

Для остальных capabilities сохраняются индекс, описание, допустимые targets, имена параметров и требования. Полный каталог доступен через объединение подробных карточек и index-only записей, без дублирования полных карточек в индексе. **Но параметры и ограничения index-only карточек не передаются во всей полноте:** это сохранение обнаружимости, не гарантия полной свободы реализации. `fullCatalog=true` явно возвращает всю документацию за тот же единственный проход. В этих восьми выборах selector этим вариантом не воспользовался.

Конфликтующие capabilities глобально не исключаются. Два движения на разных сущностях остаются допустимыми. Dependencies расширяют только документацию, не создают вызовы. Forbidden/absence-требования не становятся положительными dependencies. Полная runtime admission остаётся прежней, в том числе для index-only capabilities.

## Как тестировали

- Selector: два свежих сабагента **GPT-6 Luna**, reasoning `high`, по четыре независимых выбора с общим каталогом на каждый вариант.
- Author: 12 свежих сабагентов **GPT-6 Luna**, reasoning `high`, один предмет на сабагента: baseline + два варианта × четыре задачи. Каждый видел только свой пакет. Код, fixtures, ответы других вариантов и финальные предметы из архива были недоступны по инструкции.
- Ответы сохранялись с первой попытки. Валидатор и компилятор запускались после сохранения; ошибок моделям не возвращали, repairs не выполняли.
- Отдельный Luna-reviewer проверил bindings, producers, параметры и вторичные функции; спорные выводы перепроверены по полным ответам и каноническому Python/C# коду.
- Три контекста взяты из пользовательского `stage_requests.zip`: вампирский жезл/костюм, плита/верёвочная ловушка, мушкет/звезда. Четвёртый — явно синтетический инструмент. К каждому добавлен одинаковый для трёх вариантов stress-test brief; это не точное воспроизведение старых крафтов.
- Использован текущий Author contract; старые parent packets — только исходные факты, включая их исходные wire units. Старые `llmRawOutput` не использовались как эталон.

Это субагентный эксперимент, **не замер API**. Не было schema-constrained decoding, замеров billing/cache/reasoning tokens или сопоставимой API latency. Одно наблюдение на задачу/вариант не позволяет оценить вероятность успеха или доказать причинный эффект роутинга. Пакеты читались через инструменты; подсчёт размера ниже использует компактную JSON-сериализацию, как в production request, а не фактический служебный контекст сабагентов.

## Размер запросов

Токены — proxy `o200k_base`, не точный tokenizer GPT-6 Luna и не биллинговый usage. В таблице среднее по четырём задачам; общие provider/system wrappers и внешняя response schema не включены. Выходы указаны отдельно, hidden reasoning не измерен.

| Метрика | Полный каталог | Группы | Точные capabilities |
|---|---:|---:|---:|
| Подробных карточек для Author | 73 | 70–73 | 52–54 |
| Author input | 47 161 | 46 242 | 44 544 |
| Изменение Author input | — | −1,9% | −5,5% |
| Дополнительный selector input | 0 | 22 553 | 22 895 |
| Сумма input двух стадий | 47 161 | 68 795 | 67 439 |
| Изменение суммы input | — | **+45,9%** | **+43,0%** |
| Author output | 1 550 | 1 497 | 1 493 |
| Дополнительный selector output | 0 | 112 | 148 |
| Общий точный prefix Author по 4 пакетам | 41 535 | 31 566 | 27 115 |
| Общий точный prefix Selector по 4 пакетам | — | 16 927 | 17 269 |

Причина малого сокращения: movement/controller занимают около 6,5 тыс. токенов подробных карточек, а сам защитный индекс сохраняет существенную часть их текста. Самые объёмные группы — события, spawn-инфраструктура и equipment — защищены резервом и не исчезают. Selector также повторяет parent context.

Для холодных входов, при одинаковой цене входного токена, получаем приведённые +43–46%. Если selector дешевле Author, одно только сокращение input окупает его при отношении цен примерно ниже **11,4%** для точечного варианта или **4,1%** для группового. Это упрощённый порог без стоимости выходов, reasoning, cache, repairs и задержки.

Точный общий prefix уменьшается, но кэш не «ломается целиком»: большая общая часть сохраняется, selector получает собственный стабильный prefix. Цифры — общий prefix именно четырёх пакетов. Реальный hit rate зависит от повторяемости наборов, порядка запросов и провайдера; здесь он не измерялся. Перестановка общих карточек перед выбранными может улучшить layout, но сама по себе не устраняет второй проход и повторение parent context.

## Первые ответы и сохранение функций

| Задача | Полный каталог | Группы | Точные capabilities |
|---|---|---|---|
| Жезл + экипировка | Валиден; атака, гравитация, лечение при попадании, защита/регенерация при надевании сохранены | То же | То же |
| Мушкет + дочерняя звезда | Граф нужных функций есть, но два обязательных `bounceCount` пропущены: RED | Валиден; ammo, gravity root и on-hit homing child сохранены | Валиден; те же функции сохранены |
| Кирка + два ввода + баф в руках | RED: поля света у бафа отсутствуют; бумеранг запускается и основным вводом | Валиден, но бумеранг запускается и основным вводом | Валиден; native mining, основной прямой снаряд, отдельный альтернативный бумеранг, held ore detection/regen сохранены |
| Ловушка + размещение плиты | Валиден; управляемое зависание и размещение сохранены, автоматического выбора NPC нет | RED: два движения на одном дротике | Валиден; автоприцеливание и размещение есть, но контроллер подавляет орбитальное движение |

Штатная валидация: **2/4 → 3/4 → 4/4**. Все прошедшие ответы скомпилированы. Это не показатель «все функции сохранены»: у точечной ловушки движение не исполняется, у группового инструмента перепутана изоляция дополнительной атаки.

На трёх задачах без спорной комбинации ловушки валидность и полный запрошенный набор функций одновременно получены в **1/3, 2/3, 3/3** ответов соответственно. Это описательная сводка одной малой серии, не оценка надёжности. Точечный вариант также передаёт advisory intent: улучшение нельзя приписать только сокращению документации, отдельно от планирования и случайности генерации.

Задача ловушки оказалась проверкой ограничений композиции: курсорное зависание плюс `target_and_fire` на той же сущности не выполняются совместно. Не считаем её неудачу доказательством вреда селектора. При этом допуск неисполняемого `move_orbit` — самостоятельный пробел валидатора.

## Решение по двум реализациям

**Групповой вариант:** не внедрять в текущем виде. Он почти не сокращает Author-промпт, увеличивает общий input и в этой серии не устраняет ошибки композиции.

**Точечный вариант:** сохранить как эксперимент для качества. В этой серии он лучше собрал сложный инструмент и сохранил вторичные функции жезла/мушкета. Однако экономии общего input нет, гарантии отсутствия потерь нет, а 4/4 валидных ответов недостаточно для переключения production. Возможное оправдание дополнительной стадии — доказанное уменьшение функциональных ошибок/repairs или переход Author на более дешёвую модель; ни то ни другое эта серия пока не измеряет.

Ужесточать сокращение за счёт equipment/held/events только ради лучшей таблицы токенов не стали. Предпочтение пользователя — сохранение полезных возможностей. Более агрессивная политика должна сравниваться отдельно с теми же вторичными функциями, а не объявляться эквивалентной этой.

Найденные ограничения вынесены отдельно: [CATALOG_LIMITATIONS_RU.md](../../CATALOG_LIMITATIONS_RU.md).

Из корня репозитория (Python с зависимостями проекта; `pytest` и `tiktoken` нужны для проверки/измерения):

```bash
PYTHONPATH=LocalGenerator python -m pytest LocalGenerator/tests/test_capability_selection_experiment.py -q
python tools/experiment_capability_selection.py prepare --archive /path/stage_requests.zip --root /tmp/ifc-selection
cp -R docs/development/experiments/capability_selection_2026-10-22/selections /tmp/ifc-selection/
cp -R docs/development/experiments/capability_selection_2026-10-22/outputs /tmp/ifc-selection/
python tools/experiment_capability_selection.py assemble --root /tmp/ifc-selection
python tools/experiment_capability_selection.py evaluate --root /tmp/ifc-selection
```

CLI не вызывает модели: он строит пакеты и проверяет замороженные ответы. Для новой серии передать selector-пакет свежему GPT-6 Luna, сохранить единственный JSON по его schema; затем передать полученный Author-пакет другому свежему Luna и сохранить единственный ответ по `requiredJsonShape`. Запретить чтение остальных результатов/fixtures, запрос новых capabilities и обратную связь от валидатора до сохранения. Это воспроизводит процедуру, но не гарантирует те же случайные ответы.
