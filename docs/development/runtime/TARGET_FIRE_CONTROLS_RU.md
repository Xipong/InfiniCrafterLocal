# Управление выбором цели и огнём

`target_and_fire` остаётся независимым controller: movement, child spawn, damage и общий бюджет задаются отдельно. Дополнения ниже — явные optional-параметры с зарегистрированной нейтралью, без выбора по имени или типу оружия. Это Normalization только для объявленных технических единиц; механики не достраиваются. Сохранённый wire без полей сохраняет прежнюю идентичность; явный null не равен отсутствию.

## Предикаты цели

`minimumRangeTiles`, `coneRadians`/`coneDirection`, `bossFilter`, `minimumHealthRatio`/`maximumHealthRatio` совместно ограничивают chaseable NPC. Кольцо и конус применяются до приоритета назначенной цели и distance bias; boss использует native `NPC.boss`. Нулевая скорость не придумывает ось velocity-конуса. Границы включительны, native LOS остаётся отдельным параметром. Внутренний радиус не превышает внешний; минимальное здоровье не превышает максимальное. Клиент observer не получает нового права стрелять.

## Приоритет и ручное назначение

`targetPriority` выбирает distance, lowest_health, highest_health, closest_to_owner или facing_alignment. При равенстве сравниваются старый distance score и индекс NPC: порядок обхода не меняет результат. `player_assigned_only` стреляет только по назначенному NPC, который прошёл все те же предикаты; отсутствие цели означает удержание огня. `player_assigned_first` сохраняет назначение с переходом к выбранному приоритету. Это позволяет независимо собирать защитные, добивающие и ручные контроллеры.

## Упреждение

`aimMode=velocity_lead` вычисляет `target.Center + target.velocity × leadSeconds × 60`, затем ограничивает длину смещения `maximumLeadTiles × 16`. Изменение extraUpdates не меняет горизонт прогноза. Направление получает существующий spawn producer; дочерний `configure_spawn.aim=velocity` обязателен и никогда не переписывается. Spread применяется после прогноза. Это ограниченный линейный прогноз без предположения о будущих ускорениях NPC или скорости/траектории дочернего снаряда. Нейтраль direct полностью сохраняет прежнее поведение.

## Очереди и паузы

`warmupSeconds` добавляет однократную задержку перед первым обычным interval. `burstCount` задаёт число залпов, `burstSpacingSeconds` — промежуток внутри очереди; обычный interval разделяет последний и первый залпы соседних очередей. Каждый залп заново выбирает цель и независимо резервирует общий spawn budget; отсутствие цели не создаёт накопленной очереди. Clock использует существующий синхронизируемый controller timer и переводит world ticks в extraUpdates ровно один раз. Пауза до активации projectile не расходует warmup. Отсутствующие параметры сохраняют прежнюю периодическую стрельбу.
