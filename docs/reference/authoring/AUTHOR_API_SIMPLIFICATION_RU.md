# Упрощённый Author API: новые композиции и сохранённые предметы

[Author contract](LOW_LEVEL_RUNTIME_AUTHORING_RU.md) · [Generated inventory](../generated/LOW_LEVEL_CAPABILITY_INVENTORY_RU.md) · [Frozen Repair](../../development/pipeline/TARGETED_REPAIR_PROTOCOL_RU.md)

Это описание решений, не дополнительная схема. Точные параметры и ограничения
принадлежат registry и проецируются в каталог/provider schema.

## Граница совместимости

Свежий Author использует новые канонические формы. Убранные из каталога имена
не становятся скрытым альтернативным fresh API. Их внутренние registry-записи,
исторические receipts и сохранённый wire остаются проверяемыми; уже созданные
предметы исполняются прежними native consumers без миграции.

Новые генерации **не обещают полной поведенческой эквивалентности** прежним:
выбор целей массового урона и стадия нового масштабирования скорости изменены
намеренно. Техническое lowering новой явно выбранной формы остаётся
детерминированным, без выбора механики по названию, категории или контексту.

## Притяжение

`pull_on_event` объединяет четыре явно выбранных режима:

| mode | Смысл |
|---|---|
| `target_to_owner` | NPC к игроку; прежние NPC-параметры и правила |
| `target_to_entity` | NPC к источнику события; прежние NPC-параметры и правила |
| `owner_to_target` | Игрок к действительной цели попадания |
| `both` | Игрок и та же NPC навстречу, с независимыми явными импульсами |

В `both` отсутствие действительной цели не запускает поиск другой NPC.
Сопротивление `knockBackResist` применяется только к NPC: неподвижный босс
может остаться на месте, пока игрок подтягивается к нему. Движение игрока
остаётся owner-authoritative, движение NPC — на серверном пути с проверкой
попадания. Это не обещание атомарной синхронной физики двух тел в multiplayer.
Такую комбинацию раньше можно было собрать двумя calls; новый режим делает
её явной и закрывает случай fallback на другую цель.

## Урон ближайшим

`damage_nearby_on_event` наносит прямой урон подходящим NPC вокруг события.
Выбор: расстояние до центра, затем NPC index при равном расстоянии.
`maxTargets` выбирает до 16 ближайших; отсутствие означает технический предел
16, а не неограниченное «всех». Радиус 0.5–60 блоков и multiplier 0.05–4
сохраняют полезное объединение прежних диапазонов и событий.

Это не цепь прыжков и не запуск физических снарядов. При скоплении NPC состав
и порядок поражения нового предмета могут отличаться от прежнего slot-order
AoE. Старые `DamageArea` first-16 и `ChainDamage` nearest-12 не переписаны.

## Зависимые свойства без нового контроллера

| Каноническая capability | Необязательное свойство |
|---|---|
| `set_projectile_beam_geometry` | `ramp` |
| `attach_projectile` | `reachCurve` |
| `accumulate_projectile_charge` | `releaseEffect` |

Native компоненты остаются отдельными. `reachCurve.window` независим от окна
attachment; прежнее пересечение и отсчёт прогресса не заменяются общим таймером.
Отсутствующий объект не создаёт эффект. Особенно важно: отсутствие
`releaseEffect` не равно эффекту с единичными множителями — присутствующий
эффект всё равно задаёт launch velocity. Aim, arm pose, owner control, mana,
contact и lifetime не выбираются за Author.

Каждый вложенный leaf сохраняет точный source path в receipt. Исправление
одного неверного leaf не открывает соседние значения или принятую пустоту
для Repair. Нейтральные пропуски внутри выбранного объекта разрешены только
своими объявленными default=neutral; сам отсутствующий объект не достраивается.

## Один поздний закон скорости

Свежая `scale_projectile_velocity` умножает текущую скорость после turn и до
homing. Ноль останавливает, значения ниже единицы тормозят; optional ceiling
ограничивает итоговый модуль, отсутствие ceiling действительно означает
отсутствие cap, а не большой скрытый предел.

До двух экземпляров с доказуемо непересекающимися окнами сохраняют понятный
сценарий «сначала разогнать, затем затормозить». Окна на разных clock anchors
не считаются непересекающимися по догадке. Одна операция без окна допустима
на всю жизнь, но не вместе со вторым экземпляром. Предел два сохраняет число
прежних независимых возможностей, не вводя произвольную pipeline.

Новый API сознательно не предоставляет раннюю и позднюю стадии одновременно.
Взаимодействие с lateral oscillation поэтому может отличаться. Старые
`multiply_projectile_velocity` и `set_projectile_speed_modifier` остаются
внутренними историческими owners и не меняют исполнения сохранённых предметов.
Новое имя исключает двусмысленное переосмысление старых receipts.

## Каталог

Редактура удаляет только буквальные повторения единиц и одинаковое описание
одной ветви/её единственного свойства. Все bounds, units, зависимости и
consumer facts остаются видимыми, без нового lookup-слоя. У armor/accessory
наследование одинаковых meanings уже существовало; размеры этих карточек
сами по себе не являются обещанием новой экономии.

Сокращение числа имён и размер реального provider-запроса измеряются отдельно.
Предел payload, исходные tooltip facts и headroom tests не ослабляются.
