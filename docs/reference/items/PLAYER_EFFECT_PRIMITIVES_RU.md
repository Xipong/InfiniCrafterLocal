# Примитивы модификаторов игрока и событийного КД

`playerEffect` — общий типизированный компонент для `accessory`,
`armor` и `generated_buff_on_use`. Его поля выбираются независимо.
В экипировке они действуют при функциональном ношении; в generated-баффе — в течение
его явно выбранной длительности, включая существующие именованные группы,
удержание и реакции. Название, категория и исходный предмет не выбирают механику.

## Событие оружия и активный модификатор

Операция `reduce_heal_cooldown_on_event` вычитает время из уже идущего
КД лечения владельца. Модель явно выбирает событие `on_hit`/`on_crit` и количество
секунд. Источник должен действительно производить соответствующее попадание.

Например, следующий фрагмент добавляет механическую операцию к собственному
попаданию клинка:

```json
{"id":"restore_on_hit","fn":"reduce_heal_cooldown_on_event","target":"item","params":{"when":"on_hit","seconds":0.5}}
```

При каждом исполнении уменьшаются настоящие `Player.potionDelay` и оставшееся
время `BuffID.PotionSickness`, с нижней границей ноль. Завершившаяся слабость
удаляется. Идентичный event action можно поставить на явно выбранный снаряд.
Событие, величина и остальная композиция оружия остаются решениями Author.

Временный бафф может независимо предоставить
`playerEffect.healCooldownOnHit`. Тогда в течение его
действия фактические попадания владельца обычными и модовыми предметами/снарядами
сокращают этот КД. Нулевой урон, чужие снаряды, мёртвый владелец и истёкший бафф
не дают применение. Это самостоятельное значение, а не обязательная часть
каждого оружия или восстановительного эффекта.

## Существующие примитивы: одна величина и один consumer

Регенерация и подсветка используют корневые параметры того же вызова
`accessory`, `armor` или `generated_buff_on_use`:

```json
{"lifeRegen":2,"regenWhen":"stationary","treasureSense":true}
```

| Author | Lowery и исполнение |
|---|---|
| `lifeRegen` | ОЗ/с, шаг 0,5; точная проекция в прежнее целое `lifeRegen = value * 2`. Бафф: -50..60 ОЗ/с; экипировка: -50..100 ОЗ/с. |
| `regenWhen` | `always` или `stationary`; условие только для этого вклада регенерации. Пропуск выбирает объявленную нейтраль `always` с отдельным receipt. |
| `treasureSense` | Нативная Spelunker-подсветка подходящих руд, сундуков, кристаллов жизни. Это флаг, не радиус и не фильтр только руды. В баффе сохраняется прежний wire `oreSenseRadiusTiles = 0/1`; в экипировке — typed `treasureSense`. |
| `treasureWhen` | Такое же независимое условие для подсветки. |

`stationary` требует нулевой скорости и отсутствия анимации использования предмета.
У баффов подходящие по условию вклады выбираются каждый тик **до** прежнего
общего ограничения регенерации (-50..60 ОЗ/с). Движение не меняет длительности
баффов и не создаёт сетевой пакет на каждом переключении условия.

Вторых `playerEffect.lifeRegenHpPerSecond`, `playerEffect.lifeRegenUnits` и
`playerEffect.highlightTreasure` нет. Старые длинные Author-spellings
`lifeRegenHpPerSecond` и `oreSenseEnabled` не являются вторым свежим API.
Native wire-значения задаёт текущий lowering с exact current receipts. Отсутствующее условие допустимо только по объявленной нейтрали; сериализация не добавляет невыбранную механику.

## Поля компонента `playerEffect`

| Author | Исполнение |
|---|---|
| `condition` | `always` либо `stationary`: нулевая скорость и отсутствие активной анимации использования предмета. Условие выбирается для всего компонента и проверяется в штатной фазе применения equipment/buff stats. Пропуск — объявленная нейтраль `always` с отдельным receipt; исходный Author остаётся неизменным. |
| `fishingPowerPoints` | 0..100 дополнительных очков силы рыбалки перед native множителями. |
| `preventLineBreak` | Предотвращение обрыва лески. |
| `allowLavaFishing` | Разрешение рыбалки в лаве при остальных допустимых условиях ловли. |
| `revealHookedCatch` | Показ улова до вытягивания. |
| `extraCrateChancePercent` | 0..100% дополнительного броска на ящик для попытки, ещё не ставшей ящиком. Несколько вкладов объединяются как `1-product(1-p)`. |
| `itemPickupRangeBlocks` | 0..40 дополнительных блоков подбора всех предметов. |
| `heartPickupRangeBlocks` | 0..40 блоков только для сердец и их праздничных вариантов. |
| `manaPickupRangeBlocks` | 0..40 блоков только для звёзд маны и их праздничных вариантов. |
| `coinPickupRangeBlocks` | 0..40 блоков только для монет. |
| `highlightDanger` | Нативная подсветка опасных клеток. |
| `highlightCreatures` | Нативная подсветка существ. |
| `nightVision` | Ночное зрение без излучения света в мир. |
| `healCooldownReductionPercent` | 0..90% сокращения базового КД следующего лечебного предмета перед native множителями. |
| `healCooldownReduction` | Дополнительное вычитание 0..60 секунд из той же новой базовой длительности после выбранного процентного сокращения, до native множителей. |
| `healCooldownOnHit` | 0..60 секунд, снимаемых с уже идущего КД за фактическое попадание владельца, пока модификатор активен. |
| `manaPotionBelowPercent` | Нативное употребление доступного маназелья при мане ниже выбранного процента максимума; 0 отключает автоматизацию. |
| `hurtImmunityBonus` | 0..5 дополнительных секунд к тому слоту неуязвимости, который использовал фактический пережитый удар. |

Общий и специализированный подбор суммируются; каждый накопленный канал ограничен
160 блоками. Дальность точно проецируется в целые native пиксели с шагом 1/16 блока.
Секунды используют общий nearest-tick контракт. Процентное сокращение новых КД
суммируется до 90%, плоское — до 60 секунд; уменьшение текущего КД всегда ограничено
оставшимся временем. Автоманазелье использует наибольший выбранный порог.
Добавочная неуязвимость суммируется до 5 секунд.

Флаги выделяют конкретные неделимые операции движка. Настраиваемые величины
исполняются численно: здесь нет выбора `Shiny Stone`, `Cross Necklace` или другого
набора заранее связанных статов/VFX. Восемь информационных приборов из прежнего
варианта #225 удалены; их выдача не входит в этот контракт.

## Исполнение и транспорт

Registry владеет Author/Repair shape и проекциями единиц; compiler выдаёт exact
leaf receipts. `PlayerEffectSpec` отвергает присутствующие null, неверные типы и
числа вне native доменов. Оборудование и бафф используют один consumer. Подбор и
новая длительность лечебного КД проходят native `GlobalItem` hooks, ловля —
`ModPlayer.ModifyFishingAttempt`, попадания — реальные item/projectile callbacks.

Generated utility snapshot имеет версию 9; клиент и сервер должны обновляться
вместе. Новый reader не принимает старый пакет как новый. Сохранённые определения
без optional `playerEffect` сохраняют прежнее отсутствие. Истечение, refresh,
смерть и authority остаются у существующего buff lifecycle.

Нативные проверки наблюдают реальные таймеры, pickup ranges, условия, отсутствие
повторного применения после истечения и фактический бинарный reader/writer.
Они не подтверждают графику мира или живой multiplayer match.

## Authority и граница проверок

Пассивные native-поля `playerEffect` материализуются и для remote-player presentation; исполнение автоматического QuickMana и сокращения действующего cooldown отдельно owner-local. Native lifecycle checks проверяют actual potion consumption/Mana Sickness, reset/dead/remote/server negatives и настоящий PostHurt callback, но не полную сетевую игровую сессию или входящий Player.Hurt целиком.

Utility snapshot wire использует версию9. Старые7/8 и неизвестныеверсии отвергаются явно; это не обещание обратной совместимости. Неполный пакет не заменяет уже принятые таймеры/модификаторы.

## Обычная нативная рыбалка

Модификаторы выше сами по себе не создают удочку. Независимый явно выбранный
binding `native_fishing` запускает нативный цикл Terraria:

```json
{"id":"cast","input":"primary_use","action":{"kind":"native_fishing","fishing":{"power":30,"castSpeed":60}}}
```

`power` — целые 1..1000 очков мощности до модификаторов игрока, наживки и среды.
`castSpeed` — положительная скорость до 240 блоков/с; compiler точно переводит
её в `castSpeedPxPerTick` (×16/60, до 64 пикселей/тик), с source-linked receipt.
Оба значения обязательны: отсутствующие параметры не достраиваются.

У этого действия фиксированы `stackCost=0` и `contactDamage=false`; их можно
явно повторить. `targetId` — единственный `item_body`, с тем же объявленным
правилом пропуска, что у других item-body actions. Действие допускается на
`primary_use` и `alternate_use`; выбранный binding определяет поля нативной
рыбалки. Сетевой снимок выбранного ввода не выполняет действия повторно.
Стиль использования/поза остаются у `item_use`.

Поплавок Wooden Bobber, леска, наживка, поклёвка и улов принадлежат Terraria.
Поплавок не является runtimeProgram entity и не получает отдельный authored PNG
или authored projectile events. Сгенерированный PNG предмета остаётся у native
held/inventory renderer. Успешный заброс производит существующее `item_body.on_use`;
подтягивание уже собственного поплавка не производит повторного on_use и не
оплачивает ману повторно. Авторская стоимость маны относится к новому забросу.

Выбранная рыбалка не расходует weapon ammo: та может независимо обслуживать
боевой `spawn_entity` на другом input. Но `ammo_item` с рыбалкой несовместим:
один native `Item.shoot` не может одновременно обозначать ammo projectile и
рыболовный поплавок. Нативная наживка не заменяется ammo или расходом собственного
стака. Эти правила не выбирают рыбалку по названию, родителям или категории.

### Сетевая граница нативной рыбалки

Выбранный ввод передаётся снимком через существующий транспорт предмета;
получатель проецирует принятое определение, но не повторяет активацию, оплату
или `on_use`. Реплика поплавка с точным свидетельством исходного предмета
(ID, instance token, definition hash, slot, input и revision) может ждать
его определение не более 300 тиков. Свидетельство идёт через нативный projectile
ExtraAI; при ожидании `timeLeft` не продлевается, новый поплавок не создаётся.
После гидратации тот же поплавок возвращается под нативные AI и отмену.
Обычные ванильные поплавки и локальный владелец этим ожиданием не изменяются.

Проверены отдельные нативные акторы и сериализация, не полный подключённый
multiplayer-сеанс. Слот курсора 58 поддержан транспортом снимка, но это не
добавляет ALT-активацию там, где сама Terraria не принимает правый клик.
