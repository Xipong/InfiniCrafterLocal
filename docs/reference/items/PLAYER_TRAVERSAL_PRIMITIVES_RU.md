# Движение игрока и VFX дополнительных прыжков

Движение задаётся общим `playerEffect` в `accessory`, `armor`
или `generated_buff_on_use`. Оружие может выдавать такой бафф через явное
использование (`apply_item_effects`) или удержание именованной группы
(`refresh_held_effect`). Для движения не нужно превращать
оружие в аксессуар. Отдельно функциональная экипировка может применить выбранную
группу через `generated_buff_on_event` на `on_hurt` или `on_enemy_kill`.
Условие `condition` относится ко всему конкретному компоненту: `always` или
`stationary` (нулевая скорость, без анимации предмета).

Параметры — независимые механики. Строительные возможности и заранее выбранные
Cloud/Blizzard/Sandstorm/Fart/Tsunami jumps не входят в этот контракт. Название,
категория и описание предмета не выбирают ни механику, ни частицы, ни звук.

```json
{
  "playerEffect": {
    "airJump": {
      "count": 2,
      "launchSpeedBlocksPerSecond": 30,
      "holdDurationSeconds": 0.25,
      "horizontalAccelerationMultiplier": 1.4,
      "horizontalSpeedMultiplier": 1.2
    },
    "gravityMultiplier": 0.6,
    "maxFallSpeedBlocksPerSecond": 15
  }
}
```

`airJump` задаёт число дополнительных прыжков (1–6), вертикальную скорость и
максимальную длительность удержания. Скорость переводится в native pixels/tick,
длительность — в целые тики по общему правилу nearest-tick rounding. Native
`ModifyExtraJumpDurationMultiplier` других модов затем может изменить длительность.
Коэффициенты горизонтального ускорения и максимальной скорости действуют только
во время этого дополнительного прыжка. Их точная нейтраль при пропуске — `1`;
compiler оставляет отдельные receipts пропусков. Механика исполняется настоящим
`tML ExtraJump` с обычным jump input, а не tooltip-описанием или ID ванильного прыжка.
Авторская скорость применяется внутри native `JumpMovement`; последующие gravity,
gliding и другие movement contributions не перезаписываются. Общий `Player.jumpSpeed`
восстанавливается до выхода из этого вызова, включая исключение.

Заряды обновляются только при native refresh движения (включая землю, native
wall-slide и grappling/rope refresh). Смена экипировки, копия предмета и повторное
наложение баффа в воздухе не пополняют заряды. Новый источник, впервые добавленный
в воздухе, получает заряды при следующем native refresh. Расход хранится по точной
идентичности определения и явно выбранного компонента (экипировка/default buff/
именованная effect group), отдельно от физической копии и времени жизни баффа.
Разные компоненты одного предмета сохраняют независимые движения и заряды. Снятие источника/истечение баффа прекращает его активный прыжок. Смерть и
выход из мира очищают движение и источники.

VFX Director получает `item_body/on_jump` только при исполняемом `airJump`.
Он сам составляет слоты VFX: геометрию, частицы, материалы, свет и звук через
обычный контракт. Дополнительный прыжок не добавляет встроенный poof, ванильную
частицу или звук. `on_jump` — presentation event: он не открывает скрытые gameplay
spawn actions. Native запуск отправляет VFX от точного активного источника; бафф
сохраняет источник и его поколение даже после расходования предмета. При удалении
или замене источника прикреплённые к нему VFX прекращаются. Сетевой пакет сохраняет
идентичность определения и поколение; held item не подменяет источник баффа.

Presentation проверяет принятые активные buff-записи и фактические функциональные
слоты экипировки, поэтому событие после source sync не ждёт следующей equip-фазы.
Такая проверка не активирует бафф, не включает ExtraJump и не выдаёт заряды.
Уже принятый короткий held-бафф сохраняет свой lifetime между сетевыми снимками,
пока удерживаются точные предмет/определение/группа и нет exhaustion. Удалённая
копия не создаёт бафф из одного held definition. После смены источника действует
обычный остаток длительности; истёкшая привязка VFX не оживает от нового снимка
с тем же wire token. Интервал utility snapshots и wire v10 не меняются.

| Поле `playerEffect` | Исполнение |
|---|---|
| `autoJump` | Повтор обычных прыжков при удержании input. |
| `gravityControl` | Native переключение направления гравитации. |
| `gravityMultiplier` | Коэффициент ускорения падения; активные вклады перемножаются, общий диапазон 0.01–25. |
| `maxFallSpeedBlocksPerSecond` | Верхний предел скорости падения; строгий положительный предел побеждает, 0 не добавляет ограничение. |
| `safeFallDistanceBlocks` | Добавочная безопасная дистанция падения без иммунитета к урону. |
| `waterBreathing` | Native gill breathing с правилами текущего мира. |
| `swimJump` | Прыжки при плавании, отдельно от дыхания. |
| `waterBuoyancy` | Плавучесть; вниз разрешает погружение. |
| `wallSlideAndJump` / `wallCling` | Скольжение/прыжок от стены либо сильный режим сцепления. |
| `breathCapacityBonus` | Дополнительные единицы запаса дыхания; native reset предотвращает накопление каждый тик. |

Режим стены объединяется с native-экипировкой после всей equip-фазы, поэтому
перестановка аксессуаров не усиливает его. Generated-плавучесть применяется после
native-перехода buoyancy → FlipperJump: сама она не выдаёт `swimJump`, но не отменяет
явно выбранное плавание или ванильные Flippers/Inner Tube.

Для `on_jump` все renderers принимают только `self`, `owner`, `hitPoint`, `velocity`
или `field`; `tip`/`tipHistory` другого удерживаемого предмета не являются источником
прыжка. Ограничение одинаково для Author/VFX Repair и native reader. Событие возникает
один раз при native `ExtraJump`-старте авторского `airJump`, не при обычном прыжке
с земли, приземлении или ванильном дополнительном прыжке.

Система координат `on_jump` не зависит от направления взгляда, `itemRotation`
или `itemLocation` удерживаемого предмета:

- Начало — `player.Center`, не автоматически точка у ног. `hitPoint` хранит центр
  в момент старта прыжка.
- Для `self`/`owner`/`field`/`hitPoint` ось `forward=(0,-player.gravDir)` направлена
  против гравитации; перпендикуляр `normal=(-forward.Y,forward.X)` задаёт положительное
  боковое смещение: вправо (`+X`) при обычной гравитации и влево (`-X`) при обратной.
- Явный `anchor=velocity` выбирает нормализованную фактическую скорость игрока:
  захваченную для event-time кадра или текущую для live-привязки. При нулевой скорости
  используется jump-forward против гравитации; перпендикуляр вычисляется тем же правилом.
- `attachment=world` фиксирует event-time начало и оси, в том числе для отложенной
  эмиссии. `attachment=source` следует точному живому jump-источнику и текущей
  гравитации (для `velocity` — текущей скорости); удаление или истечение источника
  завершает эту привязку. World-эффект заканчивает собственный ограниченный lifetime.

Смещения и повороты остаются авторскими: в гравитационной системе прыжка отрицательное
forward-смещение направлено к ногам, а source-relative rotation отсчитывается от jump-forward (либо явно
выбранной оси скорости), не от фиксированного world `+X`. Явно выбранная world-система
поворота остаётся мировой. Runtime не добавляет foot-offset, не угадывает ось картинки
и не исправляет авторскую композицию. Эти факты передаются из общего `_AIR_JUMP_RULE`
в `pipelines/vfx/prompt.py` и VFX Director, и frozen Repair; они не открывают новые
Repair permissions и не меняют wire, сохранённые рецепты или изображения.

Gravity/fall-speed применяются после native инициализации physics и до расчёта
вертикального движения, в `PostUpdateRunSpeeds`. Баффы и экипировка используют
одного typed consumer. Снимок активных баффов версии 10 содержит эти значения, условия regen/treasure и
точное поколение jump-источника; старые/повреждённые версии отклоняются.
