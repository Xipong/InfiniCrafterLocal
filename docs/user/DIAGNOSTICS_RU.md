# Решение проблем

Не меняй все настройки сразу. Сначала найди, что именно не работает: **Studio → генератор → текст → рисунок → доставка в игру**. Сохрани точное сообщение, затем исправляй указанную часть.

## Studio не открывается

| Что видно | Что сделать |
|---|---|
| BAT не находит `py`/`python`, версия ниже 3.11 | Установи Python 3.11+ с Python Launcher, затем снова открой BAT |
| Ошибка `tkinter` / Tcl/Tk | В установщике Python добавь компонент Tcl/Tk; браузерная Studio тоже использует его |
| Не удаётся создать `.venv` или записать файл | Полностью распакуй ZIP в папку с правом записи; не запускай внутри ZIP |
| Ошибка установки пакетов | Проверь интернет и точный вывод установки; затем повтори `OPEN_INFINICRAFT.bat`. Если среда повреждена, переименуй только `LocalGenerator/.venv` и повтори запуск — не cache и не config |
| Окно есть, браузер не открылся | Скопируй адрес `Infinicraft Studio: …` целиком из окна запуска |
| Браузер показывает `403` или «Сессия недоступна» | Открой Studio новым запуском BAT; старый адрес с ключом сессии больше не подходит |
| «Нет связи» в уже открытой Studio | Проверь окно запуска, нажми «Повторить»; не закрывай черновик, пока можешь восстановить соединение |

**Проверка:** видны разделы настроек и **«Студия на связи»**. Это соединение с приложением настроек, не подтверждение, что игровой генератор запущен.

## Генератор не отвечает

1. На **«Рабочем столе»** нажми **«Запустить генератор»**, затем **«Проверить»**.
2. Открой [health](http://127.0.0.1:5055/health). Если адрес не открывается, прочитай ошибку запуска в **«Диагностике»** и окне консоли.
3. Если адрес отвечает, сверь `serverRoot`/`configPath` с открытой папкой и версию с установленным релизом. [Как читать поля health](OPERATIONS_RU.md#проверить-какая-копия-работает).

| Причина | Действие |
|---|---|
| Порт 5055 занят другой копией | Останови старую копию через её Studio или исходное окно консоли; затем запускай новую |
| Отказ `409` / `generator_busy` | Дождись активной ковки/очереди или отмени её в игре и дождись подтверждения |
| После сохранения осталась старая модель | Нужен «Перезапустить безопасно»: сохранение само не меняет работающий процесс |
| Ты изменил порт в Studio | Для готового мода верни 5055: он не перенастраивается автоматически |
| Неизвестный сервер/нет сведений об активности | Выясни владельца и останови его прежним способом; не уничтожай неизвестный процесс ради освобождения порта |

Для видимой консоли можно использовать **`OPEN_INFINICRAFT.bat server`** из корня, но только после освобождения порта. [Запуск и остановка](OPERATIONS_RU.md). `ok=true` в health не проверяет ключи и модели; `serverAlive=null` у sd.cpp означает «не проверялся», а не «сломался».

## Ковка завершилась ошибкой

Открой **«Диагностика → Обновить журнал → Ошибка»**. Затем проверь **«События»** и **«Этапы»**. Там важны имя стадии, код/статус и сообщение сервиса.

| Ошибка/симптом | Конкретное действие |
|---|---|
| Авторизация: `401/403`, invalid key, OAuth | Для названного источника проверь ключ или повтори вход ChatGPT. Доступ к тексту и рисункам может отличаться |
| Quota, credits, rate limit, `429` | Проверь квоту/баланс/ограничения аккаунта; при лимите частоты дождись разрешённого интервала. Не повторяй крафт много раз подряд |
| Connection refused / network timeout | Запусти внешний сервер, проверь URL/порт/сеть; затем повтори после подтверждённого окончания прошлой операции |
| Model not found | Вставь точный model ID из своего сервиса; для Codex обнови список моделей |
| `424 llm_request_rejected`, запрос/формат отклонён | Проверь provider/model и поддерживаемый формат API. Это отказ сервиса принять запрос, не ошибка уже созданной механики; [настройка совместимого API](PROVIDERS_RU.md#совместимый-api-openai_compat) |
| Author / Gameplay / Repair, invalid generated data | Модель не выдала допустимую механику. Сохрани ошибку стадии; не редактируй рецепт вручную. После устранения причины повтори тест или выбери другую подходящую текстовую модель |
| Visual Director / VFX Director | Это текстовые стадии описания рисунка и эффектов. Проверь текстовый источник, не только image server |
| `imageBackendConfigError`, missing exe/model | Исправь выбранный источник изображения. Внешнему sd.cpp нужен работающий URL, управляемому — реальные программа и файлы |
| PNG invalid / no image / rejected background | Проверь image model, поддерживаемый размер и прозрачность. Для ошибки native alpha выбери цветной фон с удалением; [настройка спрайтов](SETTINGS_RU.md#прозрачность-выбери-один-способ) |
| sd.cpp OOM / unknown argument | Снизь исходный размер, оставь параллельность изображений 1; проверь аргументы и совместимость сборки/моделей |
| ComfyUI missing workflow/node/checkpoint | Укажи существующую API-схему и установленные модели/узлы; одного URL недостаточно |
| Disk/full/permission / local I/O | Освободи место или исправь доступ к указанной папке. Не повторяй платную генерацию, пока запись результата не работает |

После изменения источника **сохрани → безопасно перезапусти → проверь → повтори одну ковку**. Смена формата JSON не исправляет квоту, а смена image source не исправляет отказ текстовой модели. [Выбор сервисов](PROVIDERS_RU.md).

## Кузня не появляется или кнопка не работает

- Проверь, что включён InfiniCrafter Local и обе зависимости.
- Core должен лежать в обычном инвентаре; открой инвентарь. Для проверки выдай Core командой `/infinicore`.
- В A/B нужны по одному допустимому предмету. Сам Core и избранные предметы не подходят. До ковки вернуть вход можно ПКМ.
- В MP дождись подтверждения переноса от хозяина. При разной версии мода обновите всех участников.
- Шкала кузни — таймер, не процент работы нейросети. Читай статус; пока операция ждёт, не запускай её повторно другой парой.
- **«Готово; ждём места в мире»** или ожидающий возврат — освободи место для выдачи. **«Ждём подтверждения хозяина»** — восстанови соединение с хозяином и дождись решения.

## Предмет есть, а рисунка или данных нет

1. В чате игры введи **`/getinfini`**: команда повторяет синхронизацию уже созданных данных, не вызывает модель заново.
2. Проверь **`/infinicache stats`**. Если есть remembered missing/bad, можно выполнить **`/infinicache resetbad`** и **`/infinicache warm held`** для предмета в руке.
3. В MP проверь версию мода и выбранный способ доставки. Для HTTP гостям нужен доступ к публичному адресу хозяина; для `native` отдельный HTTP не требуется.
4. Если хозяин потерял PNG/описание, восстанови их из резервной копии. Повторная загрузка не восстановит отсутствующий исходный файл.

Временная картинка-заглушка означает проблему показа/загрузки, не успешную генерацию нового рисунка. Не удаляй все рецепты или cache для исправления одного предмета. [Команды и экспорт примера](COMMANDS_RU.md).

## Проверить изображения без крафта

**Необязательно.** [visual_doctor.json](http://127.0.0.1:5055/visual_doctor.json) показывает конфигурацию выбранного image source, проверки файлов и доступности записи **без создания рисунка**. Это не гарантия успешного image-запроса. Проверки могут записывать маленький тестовый файл в cache и удалять его.

Вариант с **`?probe=1`** действительно генерирует пробное изображение и может расходовать квоту или запускать локальную модель. Не используй его как безусловно бесплатную проверку аккаунта. В Studio **«Проверить пути»** проверяет файлы, не рисует. Проверка аккаунта Codex не проверяет image-доступ: [подробнее](CODEX_IMAGE_OAUTH_RU.md#выбрать-изображения).

## Логи и место на диске

Полное логирование включено для нового конфига. В Studio это **«Диагностика → Записывать промпты и этапы»** (`INFINI_TRACE_PROMPTS`). Сохрани и перезапусти для применения.

| Что | Где в фактическом cache |
|---|---|
| События и ошибки | `events.ndjson` |
| Текстовые запросы/ответы | `prompt_trace.ndjson` |
| Ход стадий и сохранённые сбои | `pipeline_trace.ndjson` |
| Отдельные снимки отправляемых сообщений | `stage_requests/*.json` |
| Последняя ошибка | `last_combine_failure.json` |
| Журнал управляемого sd.cpp | Обычно `sdcpp_server.log`, либо заданный тобой путь |

При включённом режиме запросы и ответы сохраняются полностью, без автоматической ротации. **«Событий в журнале»** ограничивает число показываемых записей, не объём архива на диске. Выключение логирования не удаляет старые файлы и не выключает обязательные данные истории/предметов. Сохранение промежуточных спрайтов регулируется отдельно.

Для очистки: сохрани нужный фрагмент ошибки, затем **«Диагностика → Очистить…»**. Она очищает только три NDJSON-журнала, не рецепты/PNG. Отдельные stage requests и дополнительные отладочные файлы удаляй вручную по проверенному пути при остановленном генераторе. Если приложение отказало из-за другой копии/cache, сначала выясни её владельца; не очищай всю папку наугад.

## Что приложить к сообщению об ошибке

Создай [issue](https://github.com/Xipong/InfiniCrafterLocal/issues) и укажи:

- версии мода и генератора, одиночная игра или MP, твоя роль;
- способ запуска и какие **типы** источников текста/изображений выбраны;
- короткие шаги воспроизведения, ожидаемый и фактический результат;
- точную стадию, код ошибки и обезличенный фрагмент журнала;
- при проблеме рисунка — [экспорт](COMMANDS_RU.md#экспорт-рисунков) или скриншот.

Приложение скрывает credentials в логах, но всё равно проверь файлы перед отправкой: prompts, имена предметов, локальные пути и другие данные могут быть личными. **Не публикуй `config.env`, OAuth-файл, API-ключи, URL Studio с токеном или полный непросмотренный архив логов.**
