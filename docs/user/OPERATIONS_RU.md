# Ежедневная работа с генератором

После [первой установки](START_RU.md) ничего не нужно собирать заново. Studio управляет LocalGenerator; сама ковка происходит в Terraria.

## Запустить перед игрой

1. Если используются внешние локальные модели, запусти API server текста и сервер изображений. Для управляемого sd.cpp файлы должны быть доступны; его запуск выполнит генератор при необходимости.
2. Для сборки со встроенной Studio открой её через **Mod Configuration → InfiniCrafter Local → Studio и настройка генератора → Открыть Infinicraft Studio** или через `InfiniCrafterLocal/Studio/OPEN_INFINICRAFT.bat` в папке сохранений tModLoader. Внешняя открывалка появляется после первого запуска из мода и использует те же данные. Для отдельной поставки открой прежнюю **[OPEN_INFINICRAFT.bat](../../OPEN_INFINICRAFT.bat)** из распакованного архива/репозитория.
3. На **«Рабочем столе»** нажми **«Запустить генератор»**, затем **«Проверить»**.
4. Когда статус станет **«Сервер отвечает»**, продолжай в Terraria.

Если генератор уже работает из этой копии с нужными настройками, повторно запускать его не нужно. Не используй несколько распакованных папок одновременно на порту 5055.

**Если Studio потеряла соединение:** оставь вкладку с несохранёнными изменениями открытой и нажми **«Повторить»**. Для внешнего запуска проверь окно открывалки; если оно закрыто, запусти её заново. Для запуска из мода снова нажми **«Открыть Infinicraft Studio»** в настройках. Адрес старой сессии может больше не подойти — новая вкладка откроет действующий адрес.

## Изменить настройки и перезапустить

1. Измени нужные поля и нажми **«Сохранить настройки»**.
2. Дождись завершения ковки. В **«Диагностика → Соединение»** можно обновить сведения о текущих запросах.
3. На **«Рабочем столе»** нажми **«Перезапустить безопасно»**.
4. Нажми **«Проверить»**, затем сверь сводку источников.

Запуск сохраняет поля только после принятой проверки; отказ из-за занятой ковки или чужого сервера не применяет черновик. **«Сохранить»** отдельно записывает файл, но не меняет работающий процесс.

**Если перезапуск отказал:**

- есть активная ковка/очередь — дождись результата или отмени ковку в игре;
- сервер принадлежит другой папке — останови его через её Studio или исходное окно консоли;
- старый сервер не сообщает достаточно данных — останови его прежним способом и открой новую копию;
- ответ непонятен или истёк тайм-аут — проверь журнал и владельца порта, не запускай второй процесс.

Проверка применённых настроек сравнивает только часть параметров: папки данных, основные источники/модель, площадку OpenRouter и автозапуск sd.cpp. Ключи и дополнительные линии не сравниваются. Поэтому после любого изменения конфигурации нужен перезапуск, даже если эта частичная проверка не показывает расхождений.

## Остановить после игры

1. Заверши текущие операции или нажми **«Отмена»** в кузне и дождись подтверждения. Если виден ожидающий возврат, освободи место и дождись выдачи материалов.
2. На **«Рабочем столе»** нажми **«Стоп»**, подтверди остановку.
3. Проверь сообщение об остановке, затем закрой Studio.

**Studio, запущенная из меню мода,** при действии **«Закрыть студию»** или выгрузке мода завершает только генератор, который запустила сама. Чужой или отдельно запущенный сервер она не останавливает. Сначала заверши ковку и дождись возврата материалов.

**При внешнем запуске** через любую из открывалок сохраняется независимый жизненный цикл: **«Закрыть студию»** закрывает интерфейс, а у генератора остаётся отдельная кнопка **«Стоп»**. Закрытие одной вкладки браузера не завершает Studio ни в одном из режимов. Сервер, запущенный вручную в консоли, останавливай **Ctrl+C** в этой консоли после завершения ковки.

**Аварийный вариант:** **«Диагностика → Аварийное управление → Принудительный перезапуск…»** требует подтверждения и может прервать ковку. Используй его только для известной зависшей копии, после сохранения ошибки. Он не заменяет отмену и подтверждённый возврат материалов; защиту от управления неизвестным сервером он не снимает.

## Проверить, какая копия работает

Открой [http://127.0.0.1:5055/health](http://127.0.0.1:5055/health).

| Поле | Что ожидается |
|---|---|
| `version` | Версия установленного генератора; для этого релиза `0.5.1` |
| `serverRoot`, `configPath` | У встроенной поставки — `Studio/runtimes/<hash>/LocalGenerator` и `Studio/data/config.env`; у отдельной — папка и конфиг её `LocalGenerator` |
| `llmProvider`, `imageBackend` | Выбранные источники текста и PNG |
| `imageBackendConfigError` | Пустое значение; иначе исправь указанный источник |
| `generationActivity.active`, `.waiting` | Активные и ожидающие запросы на момент проверки |
| `generationActivity.accepting` | Принимает ли генератор новые запросы |
| `effectiveConfig.cacheDir`, `.worldRecipesDir` | Фактические папки данных; при проверке обновления используй резервные копии своих данных, не удаляй их по номеру версии |

`ok=true` означает, что отвечает LocalGenerator. Для проверки нейросетей нужен реальный крафт. Сведения о живости sd.cpp в health могут быть `null`: здесь его специально не опрашивают.

Обычный адрес мода — **`http://127.0.0.1:5055/combine`**. Смена порта в Studio не перенастраивает готовый мод; для обычной игры не меняй его. Studio слушает свой случайный локальный порт — он не предназначен для подключения игры или друзей.

## Где хранятся твои данные

Для встроенной поставки `Studio/` ниже означает `InfiniCrafterLocal/Studio/` внутри фактической папки сохранений tModLoader (`Main.SavePath`). На Windows это обычно папка под `Документы/My Games/Terraria/tModLoader`, но путь может зависеть от OneDrive и параметров запуска. Используй папку сохранений, которую открывает сам tModLoader.

| Данные | Встроенная поставка и её внешняя открывалка | Отдельный архив/репозиторий |
|---|---|---|
| Рабочие настройки | `Studio/data/config.env` | `LocalGenerator/config.env` |
| Именованные профили | `Studio/data/gui_user_presets.json` | `LocalGenerator/gui_user_presets.json` |
| Рецепты, рисунки и журналы генератора | `Studio/data/cache/`, включая `world_recipes/` и `sprites/` | `LocalGenerator/cache/`, включая `world_recipes/` и `sprites/` |
| Код, Python и зависимости | `Studio/runtimes/<hash>/` | Распакованный `LocalGenerator/` и его `.venv/` |

Данные мода находятся в `InfiniCrafterLocal/` внутри сохранений tModLoader; миры и персонажи — в обычных папках сохранений. [Сессия ChatGPT](CODEX_IMAGE_OAUTH_RU.md#где-хранится-вход) хранится в профиле пользователя и не встраивается в пакет.

Обновление встроенной среды создаёт новую папку `runtimes/<hash>` и сохраняет `Studio/data`. После замены `.tmod` один раз открой Studio через мод: стабильная `Studio/OPEN_INFINICRAFT.bat` начнёт использовать новую распакованную среду с прежними настройками. Она может запускаться без игры. Прежняя открывалка из репозитория по-прежнему использует собственную копию `LocalGenerator` и собственные данные.

Если заданы `INFINI_CACHE_DIR` или `INFINI_WORLD_RECIPES_DIR`, сохраняй указанные ими папки, а не только стандартный cache. Относительные пути при встроенном запуске считаются от `Studio/data`, при запуске из архива — от `LocalGenerator`. **«Диагностика → Кеш»** открывает фактический локальный cache; пути работающего сервера смотри в health. sd.cpp и веса моделей остаются внешними файлами: выбирай их по фактическим путям в **«Модели и LoRA»**.

Не удаляй весь cache для очистки логов: там находятся готовые предметы и рисунки. Перед обновлением сохрани cache, рецепты, PNG, данные мода, миры и персонажей. Поддерживаемые v5-определения должны читаться после minor/advisory-правок; не очищай данные и не начинай заново только из-за смены метаданных. Рабочие исправления локального reader не означают, что они уже есть в установленном `.tmod`. [Безопасная очистка журналов](DIAGNOSTICS_RU.md#логи-и-место-на-диске), [порядок обновления](UPDATING_RU.md).

## Дополнительные способы запуска

**Необязательно; для открывалки из архива/репозитория.** Следующие команды вводятся в Windows-терминале **из корня распакованной папки**, не в чате игры. У стабильной `Studio/OPEN_INFINICRAFT.bat` из встроенной поставки эти режимы не предусмотрены — её запускают обычным двойным щелчком.

```console
OPEN_INFINICRAFT.bat doctor
OPEN_INFINICRAFT.bat setup
OPEN_INFINICRAFT.bat server
```

- `doctor` печатает Python, папку генератора, путь окружения и наличие конфига. Это проверка сведений, не тест моделей; она ничего не устанавливает.
- `setup` создаёт/обновляет `LocalGenerator/.venv` и повторно устанавливает runtime-зависимости, не заменяя личный конфиг.
- `server` запускает LocalGenerator в видимой консоли без Studio. Предварительно убедись, что порт свободен; остановка — Ctrl+C.

После подготовки окружения доступны прямые команды. Сначала перейди из корня распакованной папки в `LocalGenerator`, затем выполни нужную команду:

```console
cd LocalGenerator
.\.venv\Scripts\python.exe settings_gui.py
.\.venv\Scripts\python.exe server.py
```

Для прямого запуска важна текущая папка: относительные пути из `config.env` считаются от неё. Запуск `server.py` из корня архива может создать другой cache/папку рецептов. BAT сам выбирает `LocalGenerator` рабочей папкой; при прямом запуске сделай это вручную.

`settings_gui.py` открывает ту же браузерную Studio. Отдельного настольного интерфейса больше нет; Tcl/Tk, скрытые окна и графическая сессия для Python не нужны. Для запуска без автоматического открытия браузера добавь `--no-browser`:

```console
.\.venv\Scripts\python.exe settings_gui.py --no-browser
```

Studio напечатает локальный адрес с ключом сессии; открой его целиком в браузере на этом компьютере. Не публикуй адрес и не открывай порт наружу: Studio слушает только `127.0.0.1`. Этот режим не запускает генератор автоматически и не меняет его отдельную кнопку **«Стоп»**.

Нумерованные BAT для отдельных действий находятся в **`tools/windows/`**. Обычному игроку они не нужны. [Установщик исходников](../../tools/windows/01_INSTALL_MOD_TO_TMODLOADER.bat) предназначен для разработки и **удаляет старую одноимённую папку ModSources**; [прямой сервер](../../tools/windows/06_START_SERVER_DIRECT.bat) не проверяет владельца порта через Studio.

При ручном запуске переменные окружения терминала имеют приоритет над `config.env`. Studio запускает сервер со своими текущими полями поверх окружения. Если консольная и обычная копии выбирают разные модели/пути, проверь заданные в терминале `INFINI_…`, а не перезаписывай конфиг случайными значениями.
