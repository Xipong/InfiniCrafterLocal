# Установка и первый крафт

Основной путь для Windows — **готовый мод**, а не сборка исходников. Если ты только подключаешься к другу, установи мод по шагу 2 и перейди к [мультиплееру](MULTIPLAYER_RU.md): остальные шаги выполняет хозяин мира.

**Обновляешь прежнюю поставку?** Сначала сделай резервную копию по [инструкции обновления](UPDATING_RU.md). Поддерживаемые сохранённые v5-предметы не должны отвергаться только из-за удаления метаданных; новый мир и персонаж не требуются всем прежним 0.5.04 автоматически. Поставка 0.5.5 включает отдельный локальный reader и явный VFX `ownerLink`. Мод и генератор обновляй вместе; в мультиплеере обнови мод у хозяина и всех клиентов.

## 1. Скачай готовую поставку

На [странице 0.5.5](https://github.com/Xipong/InfiniCrafterLocal/releases/tag/v0.5.5) открой **Assets**.

- **`InfiniCrafterLocal.tmod`** — готовый мод со встроенными Studio, LocalGenerator, Python и зависимостями для Windows x64. Системный Python и архив исходников для этого запуска не нужны.
- **`InfiniCrafterLocal_0.5.5_Source_and_LocalGenerator.zip`** — исходники, отдельный генератор и документация для внешнего запуска/разработки. Распакуй весь архив в доступную для записи папку; не запускай BAT внутри ZIP. Внешняя [OPEN_INFINICRAFT.bat](../../OPEN_INFINICRAFT.bat) продолжает работать отдельно.

[START_HERE.html](../../START_HERE.html) — офлайн-книга в архиве. Старые файлы 0.5.1 не получают встроенную Studio от обновления исходников. Для внешнего генератора используй мод и архив одной версии; совместимость данных проверяй по [инструкции обновления](UPDATING_RU.md#граница-совместимости).

**Результат:** для встроенного запуска достаточно `.tmod`; для внешнего есть также папка с `OPEN_INFINICRAFT.bat` и `LocalGenerator`.

## 2. Установи мод

1. Установи Terraria и **stable tModLoader**. Не используй preview-ветку для этой инструкции.
2. В tModLoader установи и включи **ParticleLibrary** и **Luminance** через браузер модов.
3. Открой **Workshop → Manage Mods → Open Mods Folders** (названия зависят от языка игры). Если открылись две папки, выбери пользовательскую **Mods** в сохранениях tModLoader, **не Steam Workshop**. Закрой tModLoader, скопируй туда `InfiniCrafterLocal.tmod`, затем открой tModLoader и включи **InfiniCrafter Local**. Подтверди перезагрузку модов, если игра её предлагает.

Используй именно пользовательскую папку Mods, не каталог Steam и не ModSources. Её расположение зависит от профиля Windows и OneDrive; открытие из игры избавляет от поиска вручную.

**Результат:** мод включён вместе с обеими зависимостями. Версия мода — **`0.5.5`**. Прежняя `0.5.04` отображалась как `0.5.4`; новая `0.5.5` численно выше. Если игра сообщает о недостающем моде, установи названную зависимость и перезагрузи моды.

**Только разработчикам:** ModSources и **Build + Reload** нужны при изменении C#-кода. Следуй [инструкции сборки](../development/BUILD_RU.md), а не заменяй ею обычную установку.

## 3. Открой Studio

### Из сборки со встроенной Studio — Windows x64

1. В главном меню tModLoader нажми значок **IFC** в правом верхнем углу: Studio откроется в браузере. Принятый клик сопровождается звуком наковальни; пока запуск идёт, повторные клики не открывают новые окна. Та же кнопка остаётся в **Mod Configuration → InfiniCrafter Local → Studio и настройка генератора**.
2. При первом запуске дождись распаковки среды из `.tmod`. Studio откроется в браузере по умолчанию. Устанавливать Python, выполнять `pip install` или распаковывать архив исходников не требуется.
3. В фактической папке сохранений tModLoader (`Main.SavePath`) появится `InfiniCrafterLocal/Studio/`. Код и интерпретатор лежат в `runtimes/<hash>`, а настройки, профили и cache — отдельно в `data/`.

После первой распаковки можно открывать **`InfiniCrafterLocal/Studio/OPEN_INFINICRAFT.bat`** прямо из проводника и сделать для неё ярлык. Эта открывалка использует те же данные и работает независимо от игры. При следующем обновлении `.tmod` один раз открой Studio через мод, чтобы подготовить новую среду и обновить внешнюю открывалку.

### Из архива или репозитория, включая опубликованную 0.5.1

1. Установи **Python 3.11 или новее** с [python.org](https://www.python.org/downloads/). Оставь компонент **Python Launcher**. Studio работает в браузере: Tcl/Tk, скрытые настольные окна и графическая сессия для Python не нужны.
2. Дважды щёлкни `OPEN_INFINICRAFT.bat` в распакованной папке.
3. Дождись создания `LocalGenerator/.venv` и установки Python-зависимостей. Для первой установки может понадобиться интернет. Модели этим действием не скачиваются.
4. Откроется **Infinicraft Studio**. Если перенёс старый `config.env`, Studio может предложить рекомендации версии 0.5.02: прими их или оставь прежние значения; [подробности](SETTINGS_RU.md#обновление-рекомендуемых-значений-0502). Оставь окно запуска открытым. Если браузер не открылся, скопируй напечатанный адрес после `Infinicraft Studio:` целиком, включая часть `?token=…`.

Открывалка из архива продолжает использовать свой `LocalGenerator/config.env` и cache. Это отдельные данные от `Studio/data` встроенной поставки.

**Результат для обоих способов:** видны **«Рабочий стол»** и разделы настроек. Если запуск остановился на ошибке доступа к папке, среды или сети, исправь названную причину и повтори его; [подробная помощь](DIAGNOSTICS_RU.md#studio-не-открывается). Адрес Studio с ключом сессии не передавай другим людям.

## 4. Выбери текст и изображения

В [инструкции по сервисам](PROVIDERS_RU.md) выбери **один** источник текста и **один** источник изображений. Заполни только их обязательные поля:

- **«Идея и механика»** — кто придумывает свойства предмета;
- **«Изображения»** — кто рисует;
- **«Модели и LoRA»** — файлы только для управляемого локального sd.cpp.

Не включай дополнительные линии моделей, запасные источники и LoRA на первом запуске. Шаблон настроек не содержит готовых моделей или аккаунта. Облачные запросы расходуют твою квоту или деньги: сначала проверь условия выбранного сервиса.

**sd.cpp нужен только при выборе этого локального источника изображений.** Он не входит в `.tmod`: укажи путь к имеющемуся `sd-server.exe` или нажми **«Скачать sd.cpp»** рядом с полем **«Программа sd.cpp»**. Ссылка откроет последний официальный релиз; выбери подходящий пакет, распакуй его и укажи исполняемый файл. Веса моделей выбираются отдельно. Для облачного источника sd.cpp не требуется.

В **«Профили и все настройки»** доступен **«Локалка: LM Studio + sd.cpp (универсальный)»**: обычный управляемый запуск без дополнительных GPU-флагов и без заданной папки ROCm. Выбранные исполняемый файл, модели и параметры семплирования сохраняются. Отдельные профили **«sd.cpp: стандартные аргументы»** и **«sd.cpp: FLUX.2 Klein 4B / RX 6800 XT hybrid (аргументы)»** меняют только режим команды и дополнительные аргументы, не пути и не текстового провайдера. Hybrid-вариант предназначен для соответствующей сборки, а не для любого GPU. Перед применением показаны изменения; до сохранения это только черновик.

Свои флаги и остальные настройки можно сохранить кнопкой **«Сохранить как профиль»**. Именованные профили хранятся отдельно от `config.env`, без ключей и токенов. Существующий профиль заменяется только после отдельного подтверждения; отмена ничего не записывает.

Нажми **«Сохранить настройки»**.

**Результат:** Studio сообщает о записи `config.env`, а сводка показывает выбранные тобой источники. Если нужного поля нет, используй **Ctrl+K** и поиск по его названию.

Рядом с сохранением находится **«Открыть папку конфигурации»**: кнопка открывает папку активного файла настроек, в том числе при переопределённом пути. Полный путь показан там же и доступен для копирования; открытие папки не сохраняет черновик.

## 5. Запусти генератор

На **«Рабочем столе»** нажми **«Запустить генератор»**, затем **«Проверить»**. Для обычной установки оставь адрес **`127.0.0.1:5055`**: именно к нему обращается мод.

**Результат:** статус **«Сервер отвечает»**. При необходимости открой [health](http://127.0.0.1:5055/health): `version` — `0.5.5`, `llmProvider` и `imageBackend` — твоему выбору, `imageBackendConfigError` пустой. У встроенной поставки `serverRoot` указывает на `runtimes/<hash>/LocalGenerator`, а `configPath` — на `Studio/data/config.env`; у отдельной поставки оба пути относятся к её `LocalGenerator`. Эта проверка не вызывает нейросеть; ключи и доступность генерации проверятся при крафте.

Если запуск отказал из-за занятого порта или текущей ковки, не открывай второй сервер. Дождись операции или останови старую копию её собственной кнопкой **«Стоп»**. [Другие ошибки](DIAGNOSTICS_RU.md#генератор-не-отвечает).

## 6. Скуй первый предмет в Terraria

Для первой установки можно создать новый мир и персонажа. При обновлении сначала сохрани резервную копию и проверяй существующие предметы на копии сохранений по [инструкции обновления](UPDATING_RU.md); удаление метаданных само по себе не требует начинать заново.

1. Создай **«Сердце кузни» (InfiniCore)**: **20 дерева** из группы Wood и **1 упавшая звезда (Fallen Star)**. Верстак для рецепта не нужен. Для теста можно выдать Core командой `/infinicore` в чате.
2. Держи Core в обычном инвентаре и открой инвентарь: появится **«Кузня чудес»**. Core — ключ к панели, его не нужно класть в A или B.
3. Возьми предмет мышью и щёлкни по A; повтори для B. В каждый вход переносится **одна единица**, не весь стек. Эти две единицы расходуются при успешной ковке. Начни с ненужных обычных предметов, не с ценного оружия.
4. Убери остаток стека с курсора и нажми **«Сковать»**. Избранные предметы, пустые слоты и сам Core не подходят. До начала ковки **ПКМ по входу** возвращает материал в инвентарь.
5. Дождись сообщения **«Готово»** и выдачи нового предмета. Шкала в кузне — таймер, а не процент выполнения нейросетью.

**Результат:** получен предмет с названием, описанием и рисунком. Если он не выдан, прочитай статус кузни: при ожидании места освободи место; при ошибке открой **«Диагностика → Обновить журнал → Ошибка»** и [найди причину](DIAGNOSTICS_RU.md#ковка-завершилась-ошибкой). Для отмены используй **«Отмена»** в кузне и дождись подтверждения, вместо закрытия сервера.
