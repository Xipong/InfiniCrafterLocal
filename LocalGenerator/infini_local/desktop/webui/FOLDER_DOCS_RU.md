# Локальная веб-мастерская Infinicraft

## Владение

`index.html` — семантический shell, SVG-иконки, навигация и диалоги.
`studio.css` — адаптивная авторская композиция, типографика, фокус и состояния.
`studio.js` — клиент локального bridge, черновик, поиск, формы и подтверждения.
`assets/` — локальные шрифты Manrope / Cormorant Garamond (WOFF2), исходные SIL OFL лицензии и знак мастерской. На стороне браузера нет CDN, пакетов, облачных сервисов и платных вызовов.

Первичная поверхность — **Operate**: реальное состояние и запуск генератора, справа последовательная сборка, ниже активность и следующий шаг. Вторичная — **Configure**: индекс этапов, профили и редактируемые параметры. Визуальная система: тёплая бумага, графитовая навигация, кислотный chartreuse только для главного действия / выбора, контраст редакционной антиквы и точного гротеска. Без фальшивых предметов, метрик и SaaS-карточек.

## Контракт

Сервер подставляет `window.INFINI_BOOTSTRAP.token`. Каждый API-запрос, включая GET `/api/state`, отправляет `X-Infini-Token`. POST `/api/action` передаёт `{action, values, extra}`. URL запуска сохраняется для авторизованного обновления вкладки; токен не выводится в интерфейс, журнал или поля.

Поля и LAN-значение фиксируются до отправки POST; submitted-поля защищены от polling уже до получения action id. Правка после отправки остаётся несохранённой. Ответ POST означает только постановку в очередь. Клиент ждёт `lastAction.id`, учитывает `revision`, сохраняет введённые после отправки изменения через локальные номера правок. Успешное сохранение подтверждается `lastAction.ok` и реальным `status` с префиксом `Saved:`. Ответ студии не означает, что генератор готов; рабочий стол показывает `home` от backend. Пулы, секреты и готовность всех моделей не выдаются за проверенные.

Черновик и секреты живут только в памяти вкладки. Polling не затирает dirty-поля; нет localStorage/sessionStorage с настройками. Password-поля содержат исходные значения, а не звёздочки. `beforeunload` защищает несохранённое; Ctrl+S сохраняет, Ctrl+K ищет по всем ключам и описаниям. Поиск не индексирует значения/секреты.

Все поля backend имеют доступ через разделы, глобальный поиск и раскрытие «Все параметры». INFINI-параметры вне метаданных также доступны как дополнительные поля, значения передаются без нормализации. Неактивные поля не удаляются. Активность источников вычисляется по **локальному черновику**, а не устаревшему `fields.disabled`.

sd.cpp: сначала источник / способ запуска / URL. Внешний запуск не требует локальных EXE / весов. Управляемый запуск открывает их в «Модели и LoRA»; адаптеры и технические параметры вынесены в disclosure. Крафт остаётся в Terraria; UI не предлагает фиктивную генерацию.

## Проверка

Для проверки нужен настоящий loopback bridge; открывать файл напрямую недостаточно. В исходном PR #67 desktop/mobile проверены Chromium на реальном parent-owned bridge с изолированным конфигом, `INFINI_IMAGE_BACKEND=off`, `INFINI_USE_LLM=0` — без запросов моделей / игры. Проверены загрузка локальных шрифтов, поиск Enter, защита черновика на polling, save + GET read-back, доступность всех 129 backend-полей и отсутствие горизонтального overflow на 390 px. JS не требует unsafe-eval; Node syntax check и console/pageerror чистые.

Native browse / OAuth / принудительный restart требуют интерактивного хоста. Они подключены к существующим действиям bridge; файловый выбор не имитируется браузерным fake path. Очистка, остановка, reset и force restart имеют явное подтверждение. Принудительный restart также передаёт `extra.confirm=true`.

## Границы

Runtime, процессы, нативные диалоги, OAuth, disk writes и безопасность shutdown принадлежат `web_studio.py` и существующему desktop controller. WebUI не дублирует backend авторитет. Закрытие студии не равно Stop генератора.

## Уточнение взаимодействия и границ проверки

- Маскирование использует слова credential-ключа на границах `_`, как `settings_env`: `MAX_TOKENS` остаётся видимым числом, расширения `SECRET` / `CREDENTIAL` скрыты и исключены из предпросмотра профиля. Сохранение ключей в локальный `config.env` явно описано в подсказке.
- Мобильная навигация блокирует взаимодействие с фоном, удерживает клавиатурный фокус и возвращает его при Escape/закрытии. Выбор текущего раздела тоже закрывает меню. Закрытие студии доступно и на узком экране.
- Enter в поисковом поле выбирает результат; Enter на кнопке закрытия или на результате сохраняет обычное поведение кнопки. Ссылки помощи и фокус рабочего стола переживают обновление состояния.
- Дополнительный браузерный regression работает с настоящими `StudioServer`, HTML/CSS/JS и явно заданным snapshot, без Tk. Он не подтверждает нативные диалоги, OAuth, генерацию или игру.
- HTTP/headless Python и DOM-проверки полного JS дополнены ручной проверкой опубликованной версии на отдельном cloud desktop. Ограничение Unix sockets в shell-среде не снималось: настоящий Tk/Chromium запущен обычным способом на desktop. Точное устройство на 390 px в этом проходе не проверено; DevTools запрещены политикой браузера.

### Читаемость текста

Размер функциональных подсказок полей, пояснений запуска/готовности, диагностического текста и предпросмотра изменений поднят с 8–11 до 12 px; заголовки результатов поиска — до 13 px, технические ключи — до 11 px. Основные кнопки используют 12 px. Существующие переносы, auto-height и scroll-контейнеры сохранены. Брендинг, декоративные подписи, sidebar, компактный connection-status и save-tray не переразмечались. Изменение подтверждено на фактическом desktop-интерфейсе: пояснения читаются крупнее, ряд основных кнопок не разъехался.

### Проверка на фактическом интерфейсе

13 октября 2026 опубликованная общая ветка PR #68 запущена в отдельно распакованной копии на cloud desktop с настоящими Tk, `StudioController`, `StudioServer` и Chromium. Исходный PR использован для воспроизведения маскирования `MAX_TOKENS`; затем проверена исправленная версия, включая baseline первого запуска.

- Первый запуск без личного `config.env` чистый: baseline берётся из того же `config.example.env`, что и форма. При наличии личного конфига он остаётся источником сохранённых значений.
- Числовые лимиты 9000 / 1500 видны без password-контролов. Поиск Enter выбирает результат; Enter на кнопке закрытия закрывает поиск без перехода.
- Одна правка лимита создаёт ровно одно несохранённое поле и переживает polling/navigation. Попытка перезагрузки предупреждает о черновике.
- Подтверждённая отмена возвращает 9000 и убирает панель изменений. Сохранение 9001 убирает панель, а настоящая перезагрузка читает 9001 с диска. После проверки 9000 восстановлено и сохранено в этой одноразовой копии.
- В обычном узком окне шириной 544 px снаружи (viewport немного меньше) поля складываются вертикально, видимого горизонтального переполнения нет. Tab остаётся в открытом меню; Escape закрывает его и возвращает фокус кнопке.

Подписи профиля/разделов, вспомогательные действия и пояснение сохранения используют 12 px, а labels, значения полей, поиск и select профиля — 13 px. Мобильный минимум 16 px у полей сохранён. Композиция Atelier сохранена; улучшена читаемость рабочего интерфейса.

Точные 390 px, нативные browse/OAuth и игровые сценарии в этом дополнительном проходе не подтверждены. Генератор и провайдерные запросы не запускались, личные ключи/настройки не использовались. Ручная проверка не подменяет автоматический regression: display/browser-зависимые тесты в ограниченной shell-среде учитываются отдельно как пропуски.
